# Дополнительная практика ЛР2 

## LR2-P05. Какие файлы можно публиковать, а какие нет?
В открытый доступ можно выкладывать только учебные материалы: ноутбук lr01_runtime_order_goncharova.ipynb, текстовые файлы sample_text.txt и mini_corpus.tsv, описание проекта в README.md, журнал версий version_log.md и таблицу metadata.tsv.
Нельзя публиковать личные данные: пароли, номера телефонов, почту, чужие приватные файлы. В моём проекте module01_environment я специально проверяла все файлы перед загрузкой на GitHub.

## LR2-P06. Проверка личных данных
Я проверила README.md и остальные файлы проекта: персональных данных, паролей, телефонов и почты там нет. В metadata.tsv указаны только безопасные сведения — имена файлов, моя фамилия и язык текста.

## LR2-P08. Карточка text_card.md
Вместо отдельного файла text_card.md я сделала в папке data таблицу metadata.tsv. В ней записаны только безопасные данные: названия файлов, моя фамилия (Гончарова) и язык текста. Этого достаточно, чтобы описать данные и не нарушить правила публикации.

## LR2-P12. Что сдавать, если GitHub недоступен?
Если GitHub перестанет работать, я упакую всю папку module01_environment в ZIP-архив на компьютере, проверю, что он нормально распаковывается в новой папке, и отправлю этот архив преподавателю через личный кабинет или почту.

## LR2-X. Сравнение GitHub и ZIP-архива
**Где выше воспроизводимость?** На GitHub. Преподаватель может сразу открыть ссылку, увидеть структуру папок и файлы, ничего не скачивая. В ZIP-архиве всё то же самое, но проверяющему нужно сначала распаковать папку.
**Где выше риск ошибочной публикации?** В ZIP-архиве. Когда я архивирую папку на компьютере, туда можно случайно закинуть старые копии, мусор или что-то личное. На GitHub я выбираю файлы перед коммитом и вижу, что именно попадёт в репозиторий, поэтому контролирую состав.

# Итоговое повторение и мини-коллоквиум по модулю

## M01-CQ1. Чем notebook отличается от runtime?
Notebook — это файл .ipynb, то есть документ с текстовыми и кодовыми ячейками. Runtime — это временная среда, в которой выполняется код. Если перезапустить runtime, все переменные исчезнут, но сам файл notebook останется. В моём проекте после Restart runtime приходилось заново запускать ячейки, потому что project_title пропадал из памяти.

## M01-CQ2. Почему порядок выполнения ячеек может не совпадать с их визуальным порядком?
Потому что в Colab ячейки можно запускать вручную в любом порядке: снизу вверх, по одной или по несколько раз. Из-за этого состояние runtime может не совпадать с тем, что видно на странице. В моём ноутбуке это сначала приводило к NameError, пока я не сделала Restart runtime → Run all.

## M01-CQ3. Что доказывает Restart/Run all?
Restart/Run all доказывает, что notebook работает правильно строго сверху вниз и не зависит от случайного порядка запуска ячеек. После этой проверки в моём проекте код выполняется без ошибок.

## M01-CQ4. Какой раздел README помогает воспроизвести проект?
Раздел «Как проверить» (или «Инструкция по запуску»). Там написано, что открыть, какие файлы загрузить и как убедиться, что всё работает. У меня этого раздела сначала не было, но после замечания одногруппницы на взаимопроверке я его добавила.

## M01-CQ5. Что считается достаточным доказательством индивидуального понимания?
Когда я могу своими словами объяснить, зачем нужна каждая папка в проекте, почему файлы названы без пробелов и кириллицы, и показать, что notebook запускается после Restart/Run all. Просто сдать файл недостаточно — важно объяснить, что и как я исправила.

## M01-CQ6. Что нельзя публиковать в открытом репозитории?
Нельзя публиковать личные данные: свои и чужие пароли, номера телефонов, почту, секретные ключи доступа и приватные файлы. В моём проекте module01_environment таких данных нет.

## M01-CQ7. Почему Git-lite не равен полному Git?
Git-lite — это работа через веб-интерфейс GitHub: кнопки, создание файлов, коммиты, загрузка через браузер. Полный Git — это командная строка, ветки, слияния и работа с локальной историей. В ЛР2 мы используем только Git-lite, потому что для учебной капсулы этого достаточно.

## M01-CQ8. Какой тест вы добавите к project capsule?
Я добавлю тест на распаковку ZIP-архива в новую пустую папку и запуск ноутбука после Restart runtime → Run all. Это покажет, что относительные пути к данным (../data/) не сломались и проект воспроизводится на другом компьютере.
