# Файл-рефлексия по Лабораторной работе 2

## 1. Чему я научилась в этой работе?
Я освоила базовые принципы организации учебного проекта. Раньше все файлы у меня лежали в одной папке без чёткой структуры, а теперь я умею создавать понятную иерархию папок и давать файлам безопасные имена — без пробелов, кириллицы и лишних символов. Кроме того, я разобралась, как устроен веб-интерфейс GitHub: как создавать репозиторий, делать коммиты, оформлять README.md и вести журнал версий version_log.md. Также я поняла, зачем нужны относительные пути к данным и как проверять воспроизводимость через Restart runtime → Run all.

## 2. С какими главными трудностями я столкнулась?
Самым сложным для меня оказалось разобраться в логике GitHub и его веб-интерфейсе. Поначалу было неясно, как именно создавать папки внутри репозитория, как загружать файлы в нужные подпапки и чем отличается коммит от простого сохранения. Приходилось несколько раз перепроверять, куда попадают файлы после загрузки.

## 3. Анализ допущенных ошибок
- На этапе взаимопроверки одногруппница заметила, что в README.md отсутствует раздел «Как проверить». Из-за этого проверяющему было непонятно, как убедиться, что проект действительно воспроизводится. Я добавила этот раздел с пошаговой инструкцией: открыть ноутбук, выполнить Restart runtime → Run all и убедиться в отсутствии ошибок.
- В начале работы я пыталась перетаскивать файлы прямо в корень репозитория, не заходя внутрь созданных папок. Из-за этого структура сбивалась, и файлы оказывались не на своих местах. Позже я научилась сначала открывать нужную папку, а затем загружать в неё файлы.

## 4. План на будущее
В следующих модулях я планирую с первого дня работы создавать правильную структуру проекта: сразу заводить папки notebooks, data, docs и продумывать имена файлов. Также я буду проверять README на наличие всех обязательных разделов, особенно «Как проверить», и вести version_log параллельно с работой, а не в конце.
